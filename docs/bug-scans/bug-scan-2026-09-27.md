# Bug scan — 27 September 2026

Reviewed authentication state, staff/branch mutations, participant records and attendance history, session validation, assessment recording and reporting. This is a targeted code review with regression tests, not proof that the whole system is bug-free or a browser/deployment audit.

## Verified issues and fixes

1. **Incomplete attendance counted as absence:** the participant history used session start time rather than explicit register finalisation. Its API now includes `attendance_finalised`; the UI excludes unfinished entries and reports the excluded count. Reopening a register therefore removes it from the history totals, matching reporting.
2. **Staff promotion failed:** changing an instructor/manager to super admin retained the old branch and was rejected. The API now clears branch membership on promotion, matching account creation; the frontend clears a hidden branch selection without mutating the edit form. Managers still cannot grant this role.
3. **Malformed branch assignment caused HTTP 500:** non-object JSON bodies reached `.get()` on a list/string/number. Both manager and instructor assignment endpoints now return a safe HTTP 400.
4. **Stale session checks could overwrite logout/newer identity:** frontend checks now carry a revision. Logout and newer checks invalidate older responses, including both late successes and late failures. This only fixes frontend state ordering; Django remains the authority for authentication. Normal reloads still retain valid sessions.
5. **Birth-date validation used server-local date:** it now uses the programme's New Zealand date, consistent with consent validation.
6. **Month/quarter filters depended on browser timezone:** session filters and reporting defaults now use the programme date, including the UTC/New Zealand quarter boundary.

Backend regression tests reproduced the assignment crash, promotion rejection, missing finalisation information and birth-date boundary failure before the fixes. Regression coverage also tests frontend stale-response ordering, incomplete-register exclusion, quarter boundaries and hidden branch normalization.

## Manual checks

- Sign in as an instructor, open a participant's attendance history, then finalise/reopen one of their session registers. Revisit history: only finalised registers should affect totals.
- Sign in as a super admin, open a staff edit page, change an instructor to super admin and save. The account should have no branch. Use a disposable test account if you want to avoid changing real access.
- With slow network responses, sign out during an existing session check. Its late response must not restore the old signed-in state. A normal refresh with a valid session should still keep the user signed in.

Validation: backend regression suite, frontend tests, production build, migration consistency and diff checks. No database migration is needed. Browser interactions and live external model responses were not exercised. The pre-existing favicon change was left untouched.
