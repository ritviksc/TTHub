# ACC reporting drafts

Source IDs remain internal to generation and validation. The report display and narrative editor omit generated source-reference lines for both new and saved drafts, and statistics and saved feedback do not show ID labels. Review the narrative against the saved feedback and figures displayed in the report.

Quotation counts are a writing preference, not a validation cap: prefer 1–3 per section, while retaining additional verified excerpts when they add evidence. Exact-quote, known-source and section-reference checks apply to every included quotation, including any beyond the fourth. Generation remains bounded by its output-token allowance.

**Download PDF** opens a local print view of the displayed report and invokes the browser print dialog. Choose **Save as PDF** or the system PDF option. Export includes saved edits, reviewed feedback, figures and limitations; it excludes navigation, controls and original unredacted feedback, even if expanded on screen. The button is disabled during narrative editing. Allow pop-ups for the site if the print view is blocked. Export uses the browser without another AI call or backend request, and does not approve or submit the report to ACC.

Staff record **Who gave this feedback?** at entry time: Kaumātua (`kaumātua`), Kaimahi (`kaimahi`), Whānau (`whānau`) or Unknown (`unknown`). `Feedback.speaker` stores that type separately from the related participant/session and the recording staff member. The migration defaults existing entries to Unknown without guessing or backfilling their type. The same label appears in the feedback list, ACC source selection, review rows and saved reports.

Super admins open **Reporting → Prepare ACC report**, choose inclusive dates (or a branch quarter), and select consented feedback. The source list is paginated and selections persist across pages. Reporting copies can be redacted; the speaker type is displayed automatically and is not a report-time choice. The backend takes attribution from the saved feedback record, ignoring any speaker override in the report request. The super admin must confirm approval for ACC reporting and AI processing; changing a selection or reviewed copy clears that confirmation.

The backend checks dates, branch, consent, approval, model selection, and input size before queueing. A draft accepts 1–100 sources, at most 4,000 characters per copy and 40,000 characters total. Narrow the selection if these limits are reached; sources are never silently truncated.

The first section is **Engagement**, with a participation table for every branch in the selected scope: Entity, Location, # Participants, # New Participants, and % Engagement. All branches are included when no branch filter is selected, even branches without feedback or attendance. Location uses `Branch.region`; missing locations show Not recorded. Participants counts currently active registrations joined by the report end date, including unknown joined dates. New participants counts recorded joined dates within the inclusive period (including registrations now inactive), excluding unknown dates. Current membership and active status cannot reconstruct an exact historical roster. Engagement is attendance rate: total attendances / total roster places across finalised sessions × 100, weighted by session places rather than averaging session rates, rounded to the nearest 5 percentage points with halfway values rounded up. Thus 85.06% becomes 85% and 87.5% becomes 90%. Attendance counts and denominators remain in the snapshot. Incomplete registers are excluded. No denominator means Not available; a finalised register with everyone absent means 0%, and very small rates below 2.5% also round to 0%. Existing saved engagement tables use the same display rounding without changing their stored snapshots. Old drafts without a branch breakdown show a notice to regenerate for the table.

The saved snapshot includes the reviewed copies, original text for internal review, approval actor/time, and calculated branch engagement, participation, enrolment, and physical-testing aggregates. The provider receives only reviewed copies with source IDs, date, speaker label, branch name, reporting scope, and the aggregate allowlist, including the verified engagement table and its definitions/limitations. Original feedback, participant names/records, contact details and individual assessments are not included in the provider payload. Free-text redaction is a human review step, not automatic anonymisation. The LLM may use verified engagement figures in its narrative but does not generate the table or infer health outcomes from attendance.

`reporting/prompts/acc.py` contains the fixed instruction prompt and request builder. One low-temperature generation call (up to 6,000 output tokens) aims for 300–500 summary words in total, excluding quotations, and less when evidence is limited. Each JSON section contains its own `quotes`, `text` summary and `source_ids`; the prompt prefers 1–3 short relevant exact excerpts per section, allowing additional verified quotations without a count cap. Markdown renders the category heading, **Supporting quotations**, its quotations, then **Summary** and the section summary. There is no shared quotation appendix. Categories without quotable evidence should be omitted. The backend validates recognised titles, source IDs, exact quote matches and that each quote's source is referenced by its section. Every included section must have at least one quotation. Sections returned with empty source lists are omitted and flagged in review notes; their prose and quotations are not included. A draft must retain at least one cited section. Unknown source IDs, invented quotations and other invalid responses still fail the job. This validation cannot prove that a narrative claim or quotation is relevant to its section: the reviewer must check the saved evidence. Existing saved Markdown and edits are not rewritten; regenerate a draft for the new narrative layout.

Jobs use the existing Celery queue, deadlines, polling, safe failure messages, and audit events. Before contacting the provider, the worker rechecks the requesting user's role and selected feedback consent/scope. Successful drafts appear in **View past ACC reports**, where any super admin can inspect and edit the saved narrative. Editing does not change source statistics or constitute approval/submission to ACC. PDF export is initiated by the reviewer; there is no automatic submission.

Endpoints (all super-admin only):

- `GET /api/reporting/acc/sources/` — dates, optional branch, and page.
- `POST /api/reporting/acc/analyse/` — scope, model, reviewed sources (`id`, `text`), and `approved_for_acc_and_ai`; speaker types are copied from the recorded feedback by the backend.
- `GET/PATCH /api/reporting/acc/jobs/<id>/` — requester polling / super-admin narrative editing.
- `GET /api/reporting/acc/history/` and `history/<id>/` — completed drafts and saved evidence.

Apply the database migration with `python manage.py migrate`, and restart existing Celery workers to register `reporting.tasks.generate_acc_analysis` when deploying. No new dependencies are required.

Validation: `python manage.py test reporting audit`; from `frontend`, `node --test tests/acc-reporting.test.js tests/report-narrative.test.js tests/report-history.test.js` and `npm run build`. Tests mock the provider and do not send feedback externally.
