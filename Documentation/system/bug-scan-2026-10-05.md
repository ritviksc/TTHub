# Bug review — 5 October 2026

Reviewed local `master` at `f66a488` and `reporting` at `1a39c98`. The reporting branch contains the entire main branch plus quarters, auditing and model-selection changes. No branches were merged and no commits or pushes were made during this review. All final edits are in the working tree on `reporting`; the master branch ref is unchanged.

## Confirmed findings

### Unassigned staff could access participant documents (both branches)

`documents_for` included `branch_id=user.branch_id` in an OR filter. When staff had no assigned branch, this matched all participant documents, whose direct branch field is null. The participant's actual branch was bypassed.

Unassigned non-super-admin staff now receive only organisation-wide documents (`branch` and `participant` both null). Regression coverage checks list, detail and download access for instructors and branch managers, including that private file storage is never opened for a denied download. Existing assigned-staff and super-admin access remains covered by the document suite.

### Deleting a session linked to feedback returned HTTP 500 (both branches)

Feedback protects its session reference. The session delete endpoint did not handle the resulting `ProtectedError`. It now returns HTTP 409 with a readable explanation and preserves the session and feedback. Existing ownership rules still apply.

### Reused staff email changed the apparent identity in audit history (reporting)

The audit viewer resolved the subject's display name using its recorded email. If that email moved to a different account, old events displayed the new person's name. The failing test reproduced “Created a staff account — Replacement” for an event belonging to the original account.

The viewer now resolves the stored immutable target UUID. If the original account no longer exists, it uses the recorded identity instead of looking up the email's new owner. Malformed/missing legacy target IDs safely fall back to recorded labels.
